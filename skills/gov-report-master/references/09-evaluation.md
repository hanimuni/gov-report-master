# ⑨ 검수·평가 — 정량·정성 기준과 반려 재수행 루프

> **Phase 6에서 Read.** 무엇을 재고, 어떻게 판정하고, 미흡하면 어느 단계로 돌려보내는가.

---

## 1. 판정은 점수가 아니라 게이트다

점수 평균은 CRITICAL을 희석한다. 출처 없는 수치가 하나 있는데 다른 항목이 좋아서
"85점 통과"가 되면 안 된다.

```
PASS                CRITICAL 0 · MAJOR 0 · 정성 필수 6개 충족 · 정성 10 중 8 이상
PASS-WITH-WARNINGS  CRITICAL 0 · MAJOR 0 · MINOR/WARN 만 → 경고 목록 제시 후 사용자 확인
FAIL                CRITICAL ≥1  또는  MAJOR ≥1  또는  정성 필수 항목 미충족
```

**`unverifiable`(확인 불가)은 조용히 PASS로 넘기지 않는다.** 별도 목록으로 사용자에게 제시한다.
확인하지 않은 것은 통과가 아니다.

## 4. 유형별 룰 on/off — 오탐 차단

CORE RULE 9는 "의미 전달상 필요한 부분은 **서술식 혼용 허용**"이라고 명시한다.
`templates/03`은 "상황 묘사 서술식 가능", `templates/08`은 "**문체는 서술식 허용**",
`templates/09`는 "소리 내어 읽었을 때 자연스러운가"다. 이를 무시하면 오탐이 쏟아진다.

| 룰 | ①②⑤⑥⑦⑩ | ③ 상황 | ④ 1쪽 | ⑧ 보도 | ⑨ 말씀 |
|---|---|---|---|---|---|
| 서술형 종결 | ERROR | **WARN** | ERROR | **OFF** | **OFF** |
| 물음표·느낌표 | ERROR | ERROR | ERROR | WARN | **OFF** |
| 대구·슬로건 | ERROR | ERROR | ERROR | WARN | **OFF** |
| 한 줄 46자 | WARN | WARN | **ERROR** | ERROR(2줄↓) | OFF |
| 마커 하한 | 적용 | 적용 | **OFF** | OFF | **OFF** |

정본은 각 프로파일의 `guard_overrides` 필드다.

### 전역 마스크 — 모든 문체 검사에서 제외하는 구간
- 표 행 (`|` 로 시작)
- 인용 블록 (`>`)
- 코드펜스
- `▸` 로 시작하는 인용 줄 (언론 인용은 서술형이 정상)
- **서명·날인란** (`작성자 :` · `(인)`)
- **보고 취지 글상자**

마지막 둘은 kordoc이 실제로 오탐을 낸 구간이다(§5). 표 안 신호등 이모지는 CORE RULE 10이
명시적으로 허용한다.

### 항목부호 — 하이브리드가 정상이다
"2계열 혼용 = ERROR"로 잡으면 **실제 부처 보고서 전부가 FAIL한다.**
실측 사례는 예외 없이 3계열 하이브리드다.

| 출처 | 실제 체계 |
|---|---|
| 기획 sample-01 (교육부 2019) | `Ⅰ~Ⅴ` → `1./2./3.` → `□ ○ -` |
| 결과 sample-06 (청와대 2007) | `□ → ○ → - → * → ⇒` |
| `assets/samples/INDEX.md` 공통 관찰 | `Ⅰ·Ⅱ → 1·2 또는 ⑴⑵·①② → □·○·❍ → - → *` |

CORE RULE 9의 사다리(`Ⅰ → 1 → □ → ○ → - → ·`)는 **깊이 순서**를 정한 것이지 「단계를 다 쓰라」는
요구가 아니다. 쓰지 않는 단계는 아래에서부터 떼어 내고, 검사는 **같은 깊이의 마커 혼용**만 본다.
위계 정본은 `03-editing.md` 부록 B-1.

```
같은 depth 에서 마커 2종 이상 출현          → ERROR
장 계열(Ⅰ/1/#)과 본문 계열(□○-) 병용      → 검사하지 않는다 (정상 관행)
```

## 5. kordoc lint 결과를 그대로 받지 않는다

골든 원고 실측: 표기법 12건(error 6) · 문체 6건(error 0). 그중 상당수가 오탐이었다.

| kordoc 룰 | 우리 판정 | 근거 |
|---|---|---|
| `DATE_2DIGIT_YR` (`'26.3` 을 error) | **WARN 격하** | 실무 실측 45건 중 7건이 `’24. 12. 10.` 약식 — 소제목·표의 관행 |
| `COLON_SPACE` (`작성자 :  홍길동`) | **제외** | 서명·날인란은 본문이 아니다 |
| `LEAD_ENDING` / `LEAD_LONG` | **제외** | 보고 취지 글상자(□1+○3=4행)를 리드문 한 문장으로 오인 |
| `AI_EM_DASH` · `AI_BOLD_OVERUSE` | **advisory** | 조언용. 실패가 아니다 |

정본은 `profiles/lint-overrides.json`. **그대로 흘리면 에이전트가 무해한 경고에 반응해 본문을 망친다.**

### 편집 정성 S11~S13 — 조판을 눈으로 본다

`format-inspector`가 Phase 7에서 조판 SVG·PNG를 **띄워 놓고** 판단한다. 수치가 다 맞아도
지면이 벽처럼 보이면 반려된다.

| # | 항목 | 질문 |
|---|---|---|
| S11 | **지면 위계** | 훑었을 때 장→항목→본문→근거가 글꼴·굵기만으로 구분되는가 |
| S12 | **강조 착지점** | 볼드가 줄마다 시선을 한두 곳으로 모으는가, 흩는가 |
| S13 | **덩어리 리듬** | `□` 앞은 벌고 `*`는 붙였는가, 균질해서 벽처럼 보이는가 |

### S4를 기계로 잡는 법
Ⅲ장(How)과 Ⅳ장(What)은 **표 헤더가 다르다.**
- Ⅲ 대안 분석 → `[대안 | 장점 | 단점 | 추진가능성]`
- Ⅳ 추진 계획 → `[단계 | 기간 | 주관 | 산출물]` · `[항목 | 산출근거 | 금액]`

Ⅲ장에 일정표·예산표가 있으면 What이 How로 새어든 것이다.

### S5를 기계로 잡는 법
문제점 항목마다 대응 방안을 **명시 참조**로 잇는다.
```
○ (민원 집중) 최근 3년간 보상 민원의 36%가 승계 요구   → ☞ 개선방안 □-2
```
이 표기는 **골든 산출물이 이미 하고 있던 것**이다. 규약으로 올리면 검사가 된다.

## 7. 반려 → 재수행 루프

FAIL의 결함을 **원인 단계로 역매핑**해 그 단계부터만 다시 돈다. 전체를 다시 쓰지 않는다.

| 결함 | 되돌아갈 단계 | 재수행 범위 |
|---|---|---|
| Q6 출처 없는 수치 | **Phase 2.5** | 해당 쟁점만 재조사 |
| S2 시급성 · S3 원인분석 누락 | **Phase 3** | 4덩어리 재구성 → **G4 재승인** |
| S4 How·What 혼동 · 목차 구조 | **Phase 4** | 뼈대 수정 → **G5 재승인** |
| Q1~Q5, Q8, Q9, Q17~Q24, S6~S9 | **Phase 5** | **해당 섹션만** 재작성 |
| **Q22·Q24 (설명 층 부족)** | **Phase 5** | **`-` 층을 채운다.** 재료가 없으면 **Phase 2로 돌아가 묻는다** |
| Q10~Q13, Q16 밀도·쪽수 | **Phase 5** (본문 압축·확장) | 쪽수 초과는 `--no-cover --no-toc` 를 먼저 시도 |
| Q15 서식 칸 불일치 | **Phase 0.5** | 서식 재해부 |
| Q14 구조 검증 실패 | **Phase 7** | 빌드 재시도 |

### 루프 제어 (반드시 지킨다)
- **동일 단계 자동 재수행 상한 2회.** 이후에는 자가수정을 멈추고 결함 목록과 선택지를 제시한다
  — 강행 / 수동 수정 / 범위 축소 / 데이터 보강.
- `06-qa.json` 에 회차별로 누적해 **무엇이 나아졌는지** 보여준다.
- **뼈대(G5)를 건드리는 재수행은 반드시 사용자 재승인.** 자동 통과 금지.
  게이트를 자동으로 뚫는 순간 이 플러그인의 핵심 가치가 사라진다.
- 사용자가 어느 게이트에서든 "다시"를 말하면 그 단계부터 재수행한다.

## 8. 스크립트 출력 계약

모든 게이트 스크립트가 같은 계약을 따른다. 에이전트가 파싱해 루프를 돌 수 있어야 한다.

```
exit  0 = PASS · 1 = FAIL(CRITICAL/MAJOR) · 2 = PASS-WITH-WARNINGS · 3 = 실행 오류
stdout  {"verdict", "findings":[{"id","severity","phase_to_retry","location","message","fix_hint"}],
         "metrics":{}, "unverifiable":[]}
stderr  사람이 읽을 리포트  (--json-only 로 억제)
```

`phase_to_retry` 가 §7의 역매핑을 실어 나른다. 에이전트는 이 값만 보고 어디로 돌아갈지 정한다.

### 「재지 못한 것」을 통과로 내보내지 않는다

**검사를 수행하지 못한 것과 통과한 것은 다른 종료 코드여야 한다.** 같은 0으로 내보내면
자동화도 사람도 초록불로 읽는다. 의존성이 없어 건너뛴 검사, 검사 대상 파일이 아예 없는
경우는 **PASS 가 아니라 실행 오류(3)** 이고, 못 잰 항목은 `unverifiable` 에 남겨
사용자에게 그대로 보인다(CORE RULE — 확인하지 않은 것은 통과가 아니다).

### 게이트가 울리면 산출물보다 눈금을 먼저 본다

게이트는 **자기가 보는 것만** 잡고, 때로 엉뚱한 것을 본다. 실패가 뜨면 원고를 고치기 전에
「이 지표가 정말 그 결함을 재는가」를 확인한다. 알려진 오탐·눈금 함정:

| 현상 | 정체 | 조치 |
|---|---|---|
| T8 「표 글자 ≥ 본문」이 늘 MINOR | kordoc 이 마크다운 h1 을 **제목 상자(표)** 로 렌더한다 | 본문 표가 아니면 무시 |
| T3 가 문서를 안 고쳤는데 뒤집힘 | 중앙값은 **모집단이 바뀌면** 흔들린다(붙임 산문을 표로 옮기자 판정이 반전) | 비율 기준으로 잰다 — 지금 T3는 「표준을 벗어난 본문 문단 ≤ 25%」 |
| 쪽수가 글자를 줄여도 안 줄어듦 | 쪽수는 글자수에 **선형이 아니다**(645~667자/쪽 구간에서 100~200자 감량은 무효) | 글자수 대신 **쪽별 채움률**로 낭비 지점을 찾는다(`10-typography.md` §6-2) |

## 9. 골든 baseline — 통과 목표가 아니라 캘리브레이션 표본

`정책기획보고서_수정본_최우진.md` 는 이 방법론으로 만든 실제 산출물이지만
**템플릿 01을 완전히 만족하지 않는다.**

```
표기법 12건(error 6) · 문체 6건(error 0)
【별첨】·【검증 요약표】 없음
{{ }} 6개인데 "📌 채워넣을 데이터" 섹션 없음
```

이걸 "PASS해야 함"으로 잡으면 `draft_guard` 가 첫날부터 자기 골든을 FAIL시킨다.

```
골든 테스트 = 현재 상태를 baseline 으로 고정 + known-gap 명시
회귀 기준  = "baseline 대비 나빠지지 않을 것"
             + "known-gap(별첨·검증표·채워넣을 데이터)은 새 산출에서 해소될 것"
룰 정확도 지표 = overrides 적용 후 실질 error 가 6건 → 1건으로 줄어드는가
```
