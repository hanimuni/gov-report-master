# ⑧ 근거 확보 — 리서치 오케스트레이션

> **Phase 2.5에서 Read.** `source-researcher` 서브에이전트가 이 규칙으로 동작한다.
> ⚠️ 이 단계는 **수집만** 한다. 보고서 문장을 쓰지 않는다 — 뼈대 승인 전 본문 금지(CORE RULE 6).

---

## 1. 강도 판정 — 얼마나 조사할지 먼저 정한다

Phase 2 인터뷰 끝에 한 문항으로 판정한다. 판정이 도구 조합을 결정한다.

| 신호 | 고 | 중 | 저 |
|---|---|---|---|
| 외부 공개·언론 노출 | ✓ | | |
| 이해관계 충돌·논쟁적 | ✓ | | |
| 근거 민감 (수치가 정책을 좌우) | ✓ | | |
| 일반 내부 정책 | | ✓ | |
| 단순 정리·단기 내부용 | | | ✓ |

**강도 "저"이면 Phase 2.5를 건너뛴다.** 사용자가 준 자료만으로 진행한다.

---

## 2. 도구 역할 분담 — 한 도구에 의존하지 않는다

| 코드 | 도구 | 강점 | 언제 |
|---|---|---|---|
| **A** | **사용자 제공 자료** | 가장 신뢰도 높은 1차 근거 | **항상 — 다른 어떤 웹 출처보다 먼저 흡수** |
| B | `WebSearch` | 최신 동향·빠른 사실 확인 | 항상 |
| C | `WebFetch` | 원문 전체 확보 | 스니펫만으로 사실 확정 금지 — 맥락 잘림 위험 |
| D | `korean-law` MCP | 법령·조문·판례·해석례 | 법령을 인용할 때 **필수** |
| E | `assembly-api` MCP | 국회 의안·입법 동향 | 계류 법안이 근거일 때 |
| F | 저장소 자산 | `assets/corpus/` · `assets/samples/` | 유사 사례의 서술 방식 참고 |

| 강도 | 도구 조합 |
|---|---|
| **고** | A + B + C + D(법령 시) + E(입법 시) → **교차검증 필수** |
| **중** | A + B + C |
| **저** | A 만 (Phase 2.5 생략) |

---

## 3. 철칙

1. **한 주장 = 2개 이상 독립 출처.** 중요할수록 엄격히.
2. **1차 > 2차.** 법령·공식 통계·부처 발표 > 언론·연구보고서.
3. **스니펫으로 사실을 확정하지 않는다.** 유망한 출처는 `WebFetch`로 원문을 확보한다.
4. **출처가 갈리면 숨기지 않고 양쪽을 기록**하고 사용자에게 확인한다.
5. **출처 ID 없는 수치는 본문에 쓰지 않는다.** 추측을 사실처럼 쓰지 않기.
6. **사용자 자료의 수치·사실관계를 임의로 바꾸지 않는다.** 불확실하면 확인한다.
7. **사용자 자료와 웹 출처가 충돌하면** 숨기지 말고 양쪽을 드러낸다.

### 출처 등급
| 등급 | 무엇 | 쓸 수 있나 |
|---|---|---|
| **1차** | 법령·시행령·공식 통계(KOSIS·e-나라지표)·부처 보도자료·연구용역 최종보고서 | ✅ 본문 인용 |
| **2차** | 언론 기사·학술 논문·민간 리포트 | ✅ 단 1차로 교차확인 |
| **3차** | 출처 불명·블로그·요약 사이트 | ❌ **사용 금지** |

## 4. 산출 형식 — 근거 카드

`.gov-report/00-sources.json` 에 레지스트리로 누적한다.

```jsonc
{
  "registry": [
    { "id": "S1", "grade": "1차", "title": "국가유공자 등 예우 및 지원에 관한 법률 제12조",
      "url": "…", "accessed": "2026. 9. 2.",
      "claim": "보상금 지급 대상은 본인에 한정",
      "cross_checked_by": ["S3"],
      "counter_evidence": null },
    { "id": "S2", "grade": "2차", "title": "…",
      "claim": "…", "cross_checked_by": [], 
      "counter_evidence": "S5 는 반대 수치를 제시 — 본문에 양쪽 병기 필요" }
  ],
  "unresolved": ["연평균 사망자 수 — 1차 출처를 찾지 못함. {{ }} 플레이스홀더로 남길 것"]
}
```

**`cross_checked_by` 가 빈 배열인 1차 미만 근거는 본문에 쓰지 않는다.**
찾지 못한 값은 지어내지 말고 `unresolved` 에 넣어 Phase 5에서 `{{ }}` 로 처리한다.

## 5. 검증 요약표와의 연결

Phase 6의 검증 요약표 `확인 방법` 열에 **출처 ID를 그대로 싣는다.**

| # | 섹션 | 내용 요약 | 유형 | 확인 방법 |
|---|---|---|---|---|
| 1 | Ⅱ-1 현황 | 승계 요구 민원 36% | 사용자제공 | 사용자 제출 통계 |
| 2 | Ⅱ-2 원인 | 법 제12조상 대상 본인 한정 | AI생성 | **S1** (법령 원문) |
| 3 | Ⅲ 대안 | 소요 재정 363억 | AI계산 | **S2·S4** 기반 산출식 (§본문 각주) |

이렇게 하면 `report-auditor` 의 Q6(출처 충족률)·Q7(산술 일치율) 검사가 자동으로 가능해진다.

---

## 6. 서브에이전트 경계

`source-researcher` 는 **사용자에게 질문할 수 없다**(서브에이전트 제약이자 CORE RULE 4·8과의 정합).

정보가 부족하면 blocker report로 메인에 돌려보낸다.
```
BLOCKED: 조사 범위가 모호합니다.
  필요: "청년 공무원 이탈" 의 대상 범위 — 전 부처인지 특정 부처인지
  영향: 통계 출처가 갈립니다(인사혁신처 전체 vs 개별 부처 자체조사)
```
메인이 사용자에게 한 번에 하나씩 묻고, 답을 받아 다시 위임한다.

**그리고 보고서 문장을 쓰지 않는다.** 근거 카드만 반환한다.
여기서 문장을 쓰기 시작하면 뼈대 승인 게이트가 무너진다.
