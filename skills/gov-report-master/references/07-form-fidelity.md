# ⑦ 서식 정합 — 레퍼런스와 "거의 같은 포맷"을 어떻게 보장하는가

> **Phase 0.5(서식 해부)와 Phase 4(뼈대)에서 Read.**
> 결과물이 "우리 부처 것 같다"고 느껴지게 만드는 규칙과, 그것을 기계로 검사하는 방법.

---

## 1. 형식의 세 층 — 무엇을 바꿔도 되는가

서식의 모든 값이 같은 무게를 갖지 않는다. 셋으로 갈라야 판단이 선다.

| 층 | 값 | 바꿔도 되나 |
|---|---|---|
| **규정** | 날짜·시간·금액 표기, 항목부호 8단계, "끝." 위치, 붙임 표기, 낫표 | **안 된다.** 「행정업무의 운영 및 혁신에 관한 규정」·편람 근거. `references/06` §8 |
| **기관** | 결재선 표 구성, 로고 위치, 제목 띠 색, 글꼴 벌, 글머리 체계, 표 머리행 음영 | **○** — 부처마다 다르고 부처 안에서는 같다. 그 부처 문서 한 장 보고 상수를 갈아 끼운다 |
| **내용** | 표 칸 너비, 박스 높이, 장 번호, 결재자 수, 빈 줄 | **계산한다.** 내용 분량에 따라 자동으로 정해진다 |
| **글쓴이** | 줄간격, 강조 위치, 표지·목차 유무, 쪽 나눔 | 마크다운·옵션에서 정한다 |

**규정 층을 어기면 반려된다. 기관 층이 틀리면 "남의 부처 문서" 같다. 내용 층은 틀릴 수 없다.**
우리 게이트는 규정 층을 ERROR로, 기관 층을 WARN으로 잡는다.

## 2. 정합성은 두 방향에서 잡는다 — `binding`

```
[hard] 서식(HWPX)이 첨부됨 → 칸이 기획을 앞에서 구속
       간트가 4행인데 과제를 6개 기획하면 다시 쓴다. 사후 검증은 늦다.
          ↓ Phase 0.5 에서 해부 → Phase 4 뼈대를 제약
[soft] 서식 없음 → 18건 실측 지면 관행과 사후 대조
       PDF에는 "칸"이 없고 관행만 있다. 관행은 제약이 아니라 참조값이므로
       위반은 WARN 이고 사람이 판단한다.
```

프로파일 JSON의 `"binding": "hard" | "soft"` 가 이를 가른다.

**hard일 때는 제약의 출처를 사용자에게 반드시 밝힌다.**
> "서식이 과제 4칸을 요구하므로 개선과제를 4개로 잡았습니다."

숨기면 사용자가 왜 자기 아이디어가 잘렸는지 모른다.

### 서식 → 기획 매핑 규칙 (hard)

| 서식이 가진 것 | 기획에 어떻게 반영 |
|---|---|
| SWOT 4분면 (S/W/O/T 각 n칸) | 현황분석을 SWOT로 구성, 각 분면 항목 수를 칸 수에 맞춤 |
| 과제 배지 N개 | 개선과제를 **N개**로 구조화 |
| 간트 M행 | 추진과제를 **M개 내외**로 |
| 참고 칸 K개 | 분석틀(참고1~K) 배치 |
| 현행☞개선 박스 | 문제↔방안을 1:1 대응 형태로 서술 |

## 3. 무엇을 재는가 — 본문 밀도만으로는 절반이다

마커 수·문단 길이·표 수·쪽수는 **본문 밀도**만 잰다. 실무자가 "우리 부처 것 같다"고
느끼는 결정적 요소는 **대부분 본문 바깥**에 있다. 프로파일의 `layout_signature` 가 이를 담는다.

| 필드 | 무엇 | 왜 중요한가 |
|---|---|---|
| `purpose_box` | 보고 취지 글상자 (위 실선·아래 이중선, **4행 이내**, 마침표 없이) | 결재자가 처음 3초에 읽는 곳. 없으면 문서가 "시작"하지 않는다 |
| `emphasis_boxes` | `◈` `◇` `▣` `<요약>` | 총사업비·핵심 판단을 별도 박스로 부각하는 관행 |
| `label_density` | (괄호 소제목) 비율 — 항목의 12%, 세부의 9% 수준 | `○ (도전) …` `○ (자율) …` 처럼 핵심어를 앞에 박는 개조식 기법 |
| `conclusion_arrow` | `⇒` 결론 줄, 30자 이내 명사 종결 | 묶음 끝에 판단 한 줄. **계열·유형별로 없을 수 있다** |
| `footnote_scheme` | `*`(단어 옆) / `※`(문단 전체) / `▸`(인용) — **혼용 금지** | `02-writing.md` §7 |
| `attachment` | 붙임 개수·번호 형식·`끝.` 표기 | **붙임이 통째로 빠진 문서가 완성본으로 취급되는 사고**를 막는다 |
| `approval_line` | 결재선 직위 라벨·전결 표기 | 실무 반려 사유 1위 |
| `title_letter_spacing` | 「정 책 기 획 보 고 서」 자간 벌리기 | 2~4자 제목은 글자 사이를 띄워 폭을 맞추는 관행 |
| `running_header` | 페이지 러닝헤더 | 청와대 비서관실 계열의 지문 |

> `purpose_box` 부재와 `attachment` 부재는 **FAIL 조건**이다. 이게 없으면
> 밀도가 아무리 맞아도 "결재 올릴 수 있는 문서"가 아니다.

## 4. 계열(lineage) — 중앙값을 그냥 내면 안 되는 이유

레퍼런스 18건은 2006~2022년 **17년 폭**에 서식 세대가 셋 섞여 있다.
실무자가 "우리 것 같다"고 느끼는 건 평균이 아니라 **자기 계열**이다.

| 계열 | n | 지문 | 쓰임 |
|---|---|---|---|
| `central_2015plus` | 11 | `Ⅰ~Ⅴ` + `1.` + `□○-` | **기본값** |
| `local_gian` | 3 | **결재란 포함 정식 기안문**, `□ → ○` 2단 | 지자체·전결 문서 |
| `blue_house_2000s` | 4 | 「◇ 머리글 + `<요약>` 선행」 + **러닝헤더** | **참고용.** 현행 표기규정과 상충하므로 기본 선택 대상에서 제외 |

**Phase 1에서 보고 대상을 물을 때 계열이 자동 결정된다.**
장·차관·부처 내부 → `central_2015plus` / 지자체·전결 → `local_gian`.

표본이 계열당 3~11건으로 적으므로 **중앙값과 함께 min/max를 실어 게이트를 범위로 쓴다.**
표본 3건에 ±15% 단일값은 의미가 없다.

### 이상치 처리
부속 표(법령용어 목록·명단 등)가 본문의 몇 배로 붙은 문서는 밀도 기준을 망친다.
실측: `상황-02`(법제처 2019)는 표행 1,598 · 1,692줄로 **상황보고 중앙값을 917줄까지 밀어올렸다**
(정상값 142줄). 표행이 그룹 중앙값의 5배를 넘고 100행 이상이면 집계에서 뺀다.
제외해도 `excluded_outliers` 에 남겨 왜 뺐는지 보이게 한다 —
**문서가 나쁘다는 뜻이 아니라 '평균적 분량'의 표본이 아니라는 뜻이다.**

## 5. 실측이 없는 유형은 실측인 척하지 않는다

| 유형 | 레퍼런스 | 프로파일 |
|---|---|---|
| ① 정책검토 · ② 계획수립 | 기획 6건 | 실측 |
| ③ 상황 | 상황 4건 (스캔본 2건 제외) | 실측 |
| ⑩ 결과보고 | 결과 6건 | 실측 |
| ⑧ 설명자료 | 교안만, 사례 0건 | 교안 기준 |
| **④⑤⑥⑦⑨** | **없음** | **`"measured": false` 파생값** |

파생 유형은 **게이트의 방향만 적용하고 절대값으로 반려하지 않는다.**
`assets/samples/INDEX.md` 의 원칙과 같다 — "억지 재구성은 하지 않았다."

## 6. 유형별 게이트 방향 — 하한이 맞는 유형, 상한이 맞는 유형

"마커 밀도가 하한 미달이면 실패(한 장이 비어 보이면 실패)"는 **원페이퍼 배포용 양식의 규칙**이다.
우리 ④·⑨에 그대로 걸면 **에이전트가 1쪽 보고를 부풀린다.**

- `templates/04`: "**짧을수록** 확실히 · **많이 버린다** · **더 짧게**", "1.5쪽 초과 시 가독성 급락"
- `templates/09`: "**세부 나열 금지** — 자료 없이 들으면 이해 불가"

| 유형 | 방향 | 가장 중요한 단 하나의 지표 |
|---|---|---|
| ① 정책검토 | both | **원인 섹션의 독립 존재** (Ⅱ장 하위 "원인" 헤딩 ≥1) — 깨포2 |
| ② 계획수립 | 하한 | **기본방향(Why) 블록이 맨 앞** — "이게 없으면 하수" |
| ③ 상황 | **상한** (1~2쪽, 긴급 1쪽) | **시각 표기 밀도** — 경과 타임라인 |
| ④ 개요정리 | **상한만** | **총 줄 수 ≤ 37** (1p 실효 상한) |
| ⑤ 회의참고 | 하한 | 쟁점 블록 반복 수 |
| ⑥ 보고자료 | 하한 | 차별 키워드 라벨 수 + 문단 5줄 이내 |
| ⑦ 협의자료 | 상한 | (우리 기관)/(타 기관) 라벨 쌍 |
| ⑧ 설명자료 | 하한 | Lead 1문장 + Quote 실명 |
| ⑨ 말씀자료 | **상한만** | 키워드 3개 초과 금지 |
| ⑩ 결과보고 | 하한 | `[지표\|목표\|실적\|달성률]` 표 존재 |

프로파일의 `gate_direction` · `primary_metric` 필드가 정본이다.

## 7. 도구 분담

| 하는 일 | 도구 |
|---|---|
| PDF/HWPX → 마커·문단이 온전한 텍스트 | `scripts/normalize.py` — **모든 계측의 선행 조건** |
| 레퍼런스 16건 → 유형별 프로파일 | `scripts/extract_profile.py` (구축 1회) |
| 첨부 서식 → 스타일 ID·여백·글꼴 | `kordoc profile` |
| 첨부 서식 → **의미론적 칸 구조**(SWOT·배지·간트·참고) | `scripts/analyze_form.py` — **kordoc이 안 해준다** |
| 산출물 ↔ 프로파일 대조 | `scripts/density_guard.py` |

### 왜 정규화가 선행 조건인가
kordoc으로 정부 보고서 PDF를 파싱하면 글머리표가 깨진다. 실측(법제처 2019):

```
○ (U+25CB) 0회      ← 마커 카운트가 0으로 나온다
ᄋ (U+110B) 7회       ← 실제로는 한글 자모
"#### □ 시스템 개요"  ← □가 마크다운 헤딩으로 승격
"- - 입법계획…"       ← 대시 이중화
"…, 법제 / 업무 평가"  ← PDF 조판 줄바꿈이 문단 안에 잔존
```

정규화 없이 뽑은 숫자를 프로파일에 넣으면 **모든 후속 게이트가 잘못된 기준으로 작동한다.**
`profiles/marker-aliases.json` 이 정규화 사전이며, 새 별칭을 만나면 여기에 추가한다.
