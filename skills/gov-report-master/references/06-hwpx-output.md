## 1. 절차 (build_report.py 가 이 순서로 돈다)

```
05-final.md (제출용 B)
   ↓ ① draft_guard.py        원고 게이트 — ERROR 있으면 여기서 중단
   ↓ ② to_kordoc_md.py       ★출력측 정규화 — 우리 마커 → kordoc 깊이 계약
   ↓ ③ kordoc generate       유형별 preset·옵션 + (서식 있으면) --profile
   ↓ ④ kordoc validate       ZIP·mimetype·XML·manifest 구조 검증
   ↓ ⑤ density_guard.py      프로파일 대비 밀도·쪽수 정합
   ↓ ⑥ 텍스트 리포트          경로·쪽수·확인 6항목 (§9)
결과.hwpx + QA 리포트
```

### ★ ②단계를 건너뛰면 안 되는 이유 (실측)

두 계약이 정반대다. 우리 템플릿은 글머리표를 **글자로 쓰고**, kordoc은 **중첩 깊이**에서 부호를 만든다.
골든 원고를 변환 없이 넘긴 결과:

| | 이중 마커 | 예 |
|---|---|---|
| 변환 전 (원고 직접) | **3건** | `□ □-1  (1단계) 배우자 생계지원금 …` |
| **변환 후 (`to_kordoc_md.py` 경유)** | **0건** | `□ (1단계) 배우자 생계지원금 …` |

`## □-1 …` 처럼 `□` 뒤에 공백이 없는 제목은 `--h2-marker box` 가 `□ ` 를 한 번 더 붙인다.
그리고 ` ○ …` 는 리스트 문법이 아니므로 **둘째 줄 내어쓰기(paraPr)가 붙지 않는다.**

변환 규칙은 `scripts/to_kordoc_md.py` 의 docstring이 정본이다. 요지:
```
## □ X     → ## X            (kordoc 이 □ 를 붙인다)
## □-N  X  → ## (N단계) X     (□-N 은 우리 내부 번호 → 텍스트로 승격)
□ X        → - X       (깊이 0)      ※ X · * X · ▸ X → 그대로
 ○ X       →   - X     (깊이 1)      표·인용·코드펜스·서명란 → 손대지 않음
   - X     →     - X   (깊이 2)      ☞ 개선방안 □-2 → ☞ 개선방안 (2단계)
```

`generate`는 실패가 아니라 **경고와 함께 산출**한다. 경고를 그대로 사용자에게 흘리지 말고
`profiles/lint-overrides.json` 으로 심각도를 재정의한 뒤 전달한다(§5).

## 2. 유형 → preset·옵션 매핑

같은 원고로 실측한 결과 **preset·옵션이 쪽수를 5 / 6 / 8쪽으로 가른다.**

| preset · 옵션 | 쪽 | 표 | 붙는 것 |
|---|---|---|---|
| `보고서` | 5 | 6 | 본문만 |
| `개조식 --no-cover --no-toc` | 6 | 19 | 장헤더 배너 · 쪽번호 · 결재란 |
| `개조식` | **8** | **22** | 표지 · 목차 배너 · 로마숫자 장헤더 · 쪽번호 · 결재란 |

→ **쪽수가 넘치면 본문을 줄이기 전에 먼저 `--no-cover --no-toc` 를 시도**한다.

| 유형 | preset | 기본 옵션 |
|---|---|---|
| ① 정책검토 · ② 계획수립 · ⑩ 결과보고 | `개조식` | `--org <기관명> --approval 담당,팀장,과장` |
| ③ 상황 · ④ 개요정리(1쪽) · ⑤ 회의참고 · ⑨ 말씀 | `보고서` | `--no-cover --no-toc --no-page-numbers` |
| ⑥ 보고자료 · ⑦ 협의자료 | `보고서` (대외 시행문 성격이면 `기안문`) | `--no-cover --no-toc` / `--doc-head --doc-foot` |
| ⑧ 설명자료(보도) | `보도자료` | `--press-head --press-sub` |

정본은 `profiles/NN-*.profile.json` 의 `kordoc` 필드다. 이 표는 요약이다.

### 본문 서식 옵션
`--font gothic|myeongjo` · `--pt <크기>` · `--line-spacing <%>` · `--bullet2 ㅇ|○` ·
`--h2-marker box|number|none` · `--fonts "body=…,heading=…,ref=…,table=…"` · `--sizes "dae=16,cham=13,…"` ·
`--suppress-single`(단일 항목 부호 생략 — 편람 규정)

## 3. 레퍼런스 서식 재현 (`--profile`)

```bash
npx -y kordoc@^4 profile <레퍼런스.hwpx>          # 표 서식 → JSON
npx -y kordoc@^4 generate 초안.md -o 결과.hwpx --preset 개조식 --profile <서식.json>
```

실측 확인: 레퍼런스 프로필을 주입하면 borderFill 24→40, charPr 38→53으로 늘고
**레퍼런스 고유색 `#1F3864` 가 실제로 주입된다.**

> ⚠️ **한계 둘**
> 1. `--profile` 은 kordoc 기본값을 **대체하지 않고 더한다**(24→40, 9가 아님). 즉 **표(borderFill·charPr·열폭)만** 재현하고 **본문 문단 스타일은 preset이 지배**한다. 본문까지 맞추려면 `--fonts` `--sizes` `--pt` `--line-spacing` `--bullet2` 를 함께 준다.
> 2. `kordoc profile` 은 stdout이 아니라 **입력 파일 옆에 `<이름>.profile.json` 을 쓴다.** 반드시 `-o` 로 `.gov-report/` 안을 지정해 사용자 폴더를 오염시키지 않는다.

의미론적 칸 구조(SWOT 4분면·과제 배지 수·간트 행)는 `kordoc profile` 이 **주지 않는다** →
`scripts/analyze_form.py` 가 슬롯·layout_signature·제약 문장을 함께 뽑는다. `references/07-form-fidelity.md` 참조.

## 4. 함정 (실측으로 확인된 것)

| 함정 | 사실 |
|---|---|
| `render --reflow` | **v4.12.0에 없다**(reflow가 기본값, `--no-reflow` 만 존재). 다만 우리는 **SVG를 만들지 않는다** — §9 참조. 쪽수는 `render` 가 stderr 로 내는 `(N페이지 …)` 를 파싱해 얻는다 |
| `--preset` 위치 | **`generate` 서브커맨드 뒤에만** 붙는다. 최상위에 붙이면 unknown option |
| `-o` 경로 | POSIX 절대경로(`/c/...`, `/d/...`)를 주면 Windows에서 못 찾는다. 프로젝트 하위 상대경로를 쓴다 |
| 한글 경로 | 항상 따옴표로 감싼다. Python 쪽은 `PYTHONUTF8=1` 필수 |
| 미상 preset | 에러가 아니라 **조용히 `기안문`으로 폴백**한다. 오타 주의 |
| 전용 옵션 오용 | `--doc-head`(기안문 전용) 등을 다른 preset에 주면 에러가 아니라 **warning 후 무시** |
| 패키지 구조 | 생성본 6파일 vs 한컴 저장본 11파일(`version.xml`·`settings.xml`·`PrvImage.png`·`container.rdf`·`manifest.xml` 없음). `section0.xml` 도 70KB vs 145KB(원본엔 `linesegarray` 조판 캐시). **바이트·엔트리 비교는 무의미 — 텍스트·마커·문단 레벨로 비교한다** |
| PDF 덮어쓰기 | 한컴 COM 은 대상 PDF 가 이미 있으면 **덮어쓰기 확인 대화상자에서 무한 대기**한다. 저장 전에 대상 파일을 지우거나 매번 새 이름을 쓴다 |
| 각주 위치 | HWPX 각주는 `<hp:ctrl><hp:footNote>` 를 반드시 **`<hp:run>` 안쪽**(닫는 `</hp:run>` 앞)에 넣는다. 문단 직속으로 두면 한글이 **오류 없이 통째로 무시**한다. 번호는 문장 끝에 와야 읽히므로 그 문단의 마지막 런 끝에 붙인다 |

## 5. lint 결과를 그대로 받지 않는다

`kordoc lint` (표기법 13룰) 와 `lint --munche` (개조식 문체 12룰)는 강력하지만,
**우리 실측 관행보다 엄격하거나 우리 문서 구조를 오해하는 경우**가 있다.

| kordoc 룰 | 우리 판정 | 근거 |
|---|---|---|
| `DATE_2DIGIT_YR` (`'26.3` 을 error) | **WARN 격하** | 실무 실측 45건 중 7건이 `’24. 12. 10.` 약식 — 소제목·표에서 쓰는 관행이다 |
| `COLON_SPACE` (`작성자 :  홍길동`) | **제외** | 서명·날인란은 본문이 아니다 |
| `LEAD_ENDING` / `LEAD_LONG` | **제외** | kordoc이 **보고 취지 글상자**(□1 + ○3 = 4행)를 리드문 한 문장으로 오인 |
| `AI_EM_DASH` · `AI_BOLD_OVERUSE` | **advisory** | 조언용 warning. 실패가 아니다 |

정본은 `profiles/lint-overrides.json`. `draft_guard.py` 가 kordoc JSON을 받아 이 표대로
승격·격하·제외한 뒤 최종 판정한다. **그대로 흘리면 에이전트가 무해한 경고에 반응해 본문을 망친다.**

## 6. 마크다운 작성 규약 (kordoc이 인식하는 형식)

### 항목부호는 손으로 타이핑하지 않는다
**중첩 리스트의 깊이가 부호를 결정한다.** 들여쓰기 2칸 = 한 단계.

| 깊이 | 들여쓰기 | 부호 | 깊이 | 들여쓰기 | 부호 |
|---|---|---|---|---|---|
| 0 | 0칸 | `1.` | 4 | 8칸 | `(1)` |
| 1 | 2칸 | `가.` | 5 | 10칸 | `(가)` |
| 2 | 4칸 | `1)` | 6 | 12칸 | `①` |
| 3 | 6칸 | `가)` | 7 | 14칸 | `㉮` |

```
1. 첫째 항목            ← 깊이0 → "1."
  - 둘째 항목           ← 깊이1(2칸) → "가."
    - 셋째 항목         ← 깊이2(4칸) → "1)"
```
마커 종류(`-` / `1.`)는 무시되고 **깊이만** 본다. 엔진이 부호와 둘째 줄 내어쓰기를 넣는다.
`보고서`·`개조식` preset에서는 깊이가 `□ ○ - ㆍ` 불릿으로 나온다.

> ⚠️ **`###` 소제목이 있으면 부호가 한 단계씩 밀린다** (실측 확인).
> `### 1. 현황` 은 조판에서 `□ 1. 현황` 으로 나오므로, 그 아래 깊이 0 항목은 `□` 가 아니라 `○` 로,
> 깊이 1은 `-`, 깊이 2는 `ㆍ` 로 렌더된다. 결과 계층은 `□(소제목) → ○ → - → ㆍ` 로 **정부 관행과 일치**하지만,
> **`density_guard` 의 Q10 마커 대조는 이 이동을 모른다** — 원고에서 `○` 로 쓴 항목이 산출물에서는 `-` 로 잡혀
> `-` 밀도가 과다한 것처럼 보인다. 소제목을 쓴 문서의 Q10 결과는 이 점을 감안해 읽는다.
> (`--bullet2` 로는 교정되지 않음 — 그 옵션은 다른 단계를 건드린다.)

> ⚠️ **`density_guard` 는 본문에만 돌린다.** 프로파일은 본문 기준으로 실측됐다.
> 별첨을 붙인 전체 문서로 재면 마커·문단이 몇 배가 되어 Q10~Q12 가 무의미하게 FAIL 한다.
> 반대로 본문만 잘라 재면 붙임이 없으므로 **Q16(붙임 존재)은 전체 문서로 따로 확인**해야 한다.

- **항목이 하나뿐이면** 리스트로 만들지 말고 본문 단락으로 쓴다(편람: 단일 항목 부호 생략).
  CLI 기본은 하나여도 부호를 붙이므로 생략하려면 `--suppress-single`.
- 대제목은 `#`, 장은 `##`. 개조식 preset에서 첫 `#` 은 표지 제목, `##` 은 로마숫자 장 헤더가 된다.
- 가운데 정렬(기관명·발신명의)은 `<center>○ ○ 구 청 장</center>` 한 줄로.
- 표는 GFM 파이프표. 병합·중첩이 필요하면 HTML `<table>`(colspan/rowspan).
- 수식은 `$$...$$` → HWPX 네이티브 수식. 차트는 ` ```chart ` 펜스(펜스 안 주석 금지).

## 7. 마크다운 → HWPX 서식 표준 (정부 보고서)

> ⚠️ 이 절은 요약이다. **수치의 정본은 `10-typography.md`** (부처 업무보고 3건 실측)이며,
> 충돌하면 그쪽이 이긴다. 기계가 읽는 값은 `profiles/typography.json`.

- **기본 글자**: 함초롬바탕 15p (표지 제목 HY헤드라인M 32p, 장 16p, 항목 15p, 각주 맑은 고딕 12p)
- **편집여백**: 위 10mm, 아래 10mm, 좌·우 **20mm** (머리말·꼬리말 10mm)
  — 좌·우 20mm는 기재부·인사혁신처·농식품부 3건이 모두 같았다. 분량이 모자란다고 줄이지 않는다
- **줄간격**: **160%** (각주 130%)
  — 130%는 **기안문(맑은 고딕 11.5p)** 값이다. 보고서에 쓰면 지면이 눌린다
- **항목부호**: `Ⅰ → 1 → □ → ○ → - → ·` 한 사다리 + 보조선 `※`(참고·유의)·`*`(출처·각주)
  단계는 내용의 구조화 필요성이 정하고, 쓰지 않는 단계는 아래에서부터 뗀다 — 정본은 `03-editing.md` 부록 B-1
  (장(章) 계열과 본문 계열의 병용은 실제 부처 보고서의 정상 관행이다 — `09-evaluation.md` §항목부호)
- **들여쓰기**: 하위는 상위 기호의 글자 위치 +2타, 두 줄 이상이면 둘째 줄을 첫 글자에 맞춘다(T4)
- **표 글자**: 함초롬바탕 **12~13p**(본문보다 작게), 셀 여백 좌·우 3pt
- **머리말**: 우측 정렬 — **일자 · 작성 부서 · (작성자)**
  ⚠️ 이 자리에 **문서 성격이나 주제를 넣지 않는다**(`13-writing-operations.md` §6).
  글꼴 지정값은 실측 근거가 없어 삭제한다 — 본문 기준을 따른다
- **강조**: 핵심 단어 **굵게** 또는 파란색(강렬한 원색 자제). 순서어(첫째·둘째)는 고딕
- **숫자**: 아라비아 숫자 (예: 29)
- **정렬**: 왼쪽 정렬 기본, 문장은 의미 단위로 호흡을 끊어 배치

### 유형별 제목상자 색상(관례)

## 8. 2025 개정 공문서 작성 규정 (표기 정확도 — 필수)

정부 공문서·보고서 산출 시 아래 규정을 지킨다. **서식 오류로 반려되는 대표 항목이다.**
`kordoc lint` 13룰이 이 중 상당수를 자동 검사한다.

### 날짜·시간·금액
- **날짜**: 아라비아 숫자 + **일 다음 반드시 마침표**. `2025. 1. 6.`(O) / `2025. 1. 6`·`2025.1.6`(X). **연도·월·일 사이에 쉼표 안 씀.**
- **요일**: `2025. 1. 6.(월)`(O) / `2025. 1. 6(월).`(X).
- **기간**: 물결표(~) 또는 붙임표(-), "까지" 중복 금지, 연도 겹치면 뒤 생략. 예) `2025. 1. 6.~1. 10.`
- **시간**: 24시각제, 십 미만 0 삽입, 쌍점(:) 양쪽 안 띄움. `09:00`·`13:20`(O) / `오후 13:00시`(X).
- **금액**: `금113,560원(금일십일만삼천오백육십원)` — "금" 붙여쓰기 + 괄호 안 한글 병기.

### 항목부호·표시위치
- **8단계**: `1. → 가. → 1) → 가) → ⑴ → ㈎ → ① → ㉮`, 특수부호 `□ ○ - •`. 항목기호=순서·우선순위, 특수부호=대등 병렬.
- 첫째 항목은 제목 "제"자 위치에서 시작, 하위는 앞 항목보다 2타 우측, 기호와 내용 사이 1타.

### "끝." 표시 (4경우)
- 본문이 끝나면 1자(2타) 띄우고 `끝.`
- 본문이 오른쪽 한계선에서 끝나면 → 다음 줄 왼쪽 기본선에서 1자 띄우고 `끝.`
- 붙임물이 있으면 붙임 표시 끝에 → `붙임∨∨예산 내역서∨1부.∨∨끝.`
- 연명부는 칸 밖 왼쪽 아래에 `끝.`

### 붙임·관련 근거
- **붙임**: "붙임" 다음 1자(2타) 여백. 여러 개면 묶지 말고 `1. …1부. / 2. …1부.` 각각. 별도 발송은 "별도 보냄".
- **관련 근거**: `1. 관련: 처리과명-번호(날짜)「문서명」` — 문서 명칭 반드시 포함, 날짜 앞선 것부터.

### 수신·기타 표기
- **수신**: 내부결재는 "내부결재"(발신명의 미표시). 직위 뒤 (보조/보좌기관 직위). 민원회신은 성명+"귀하" `[우.우편번호 도로명주소]`. 다수는 "수신자 참조".
- **낫표**: 겹낫표 『 』 = 책·신문명, 홑낫표 「 」 = 법률·규정·소제목·작품·상호·곡명.
- **붙여쓰기**: 국가명·기관명·기구명·단체명·직위명은 붙여 씀(예: 행정안전부장관, 세계보건기구). 도로명 주소에 사이시옷 안 넣음.
- **한글 병기**: 한글이 원칙, 외국문자는 괄호 안. `연구 개발(R&D)`(O) / `R&D`(X).
- **강조·표 축소 한계**: 표 안=글자색·진하게·바탕색·테두리 / 표 밖=글자색·밑줄·진하게(밑줄은 표 안 불가). 표 글자 축소는 기본값에서 **2pt 이내**, **장평 90%·자간 -10%가 최대치**.

## 9. 쪽수·완결성

- 레퍼런스 양식이 있으면 **최종 쪽수를 레퍼런스와 동일하게** 맞춘다. 넘칠 것 같으면
  ① `--no-cover --no-toc` 로 부속 페이지를 먼저 줄이고 ② 그래도 넘치면 **본문을 압축·요약**한다.
  자간·장평 축소 같은 **'가짜 줄이기'는 금지**(`02-writing.md`).
- ③ 상황보고는 "신속성이 생명"이므로 **쪽수 동일성을 요구하지 않고 상한(1~2쪽, 긴급 1쪽)만** 본다.
- ④ 개요정리는 **1쪽이 실패 조건**이다. 1.5쪽을 넘기면 FAIL.
- `kordoc validate` + `density_guard.py` **둘 다 통과**해야 완료로 본다.

### 산출 리포트 — 전부 텍스트로 낸다

**조판 프리뷰(SVG)는 만들지 않는다.** kordoc `render` 는 한컴의 실제 조판이 아니라 자체 reflow
엔진의 **근사치**이고, 사용자는 한컴오피스라는 **정본**을 갖고 있다. 근사치가 틀렸을 때
잘못된 확신을 주는 것이 값어치보다 크다. 쪽수는 kordoc이 숫자로 주므로 그림이 필요 없다.

```
✅ 산출 완료
   <출력 경로>.hwpx   (N쪽 · 표 M · 구조검증 통과)

   한글에서 열어 확인하실 것 6가지
   1. 쪽 넘김 — □ 소제목이 쪽 맨 아래 혼자 남았는지
   2. 표 걸침 — 표 헤더와 첫 행이 갈렸는지
   3. 분량 — 목표 N~M쪽 (현재 K쪽)
   4. 제목상자 색 — <유형> = <색상>
   5. 붙임 순서 ↔ 본문 언급
   6. 결재선 — <직위 라벨>
```

실무 반려 사유 1위는 조판이 아니라 **결재선·붙임·숫자**다. 4·5·6번은 조판을 봐도 알 수 없고
`report-auditor` 결과에서 온다. 그 결과를 같은 리포트에 병기한다.

| # | 항목 | 어디서 오나 |
|---|---|---|
| 1 | 쪽 넘김 위치 | 사람이 한글에서 확인 |
| 2 | 표 헤더와 첫 행 분리 | 사람이 한글에서 확인 |
| 3 | 분량 (④는 1쪽이 실패 조건) | `density_guard` 가 숫자로 판정 |
| 4 | 제목상자 색이 유형 규정과 맞는가 | 사람이 한글에서 확인 |
| 5 | **숫자 3중 대사** — 본문 ↔ 표 ↔ 합계 | `report-auditor` |
| 6 | **붙임 ↔ 본문 언급 · `끝.` 위치 · `{{ }}`·`[AI]` 잔재 0** | `report-auditor` + `draft_guard` |

## 11. 표를 직접 심을 때 — 쪽 나눔과 칸 높이

붙임(참고)을 표로 짤 때 반드시 안다. **표 조판의 실패는 내용이 아니라 지면에서 난다.**

### 11-1. ★표는 쪽 경계에서 나뉘지 않는다

`<hp:pos treatAsChar="1">` 로 심은 표는 `pageBreak="CELL"` 을 줘도 **갈라지지 않고
통째로 다음 쪽으로 밀린다.** 그래서 한 쪽 분량의 표 앞에 `□` 제목 한 줄만 놓아도
그 쪽이 20%만 차고 표는 다음 쪽으로 간다 — 지면 하나를 통째로 버린다.

| 증상 | 원인 | 조치 |
|---|---|---|
| 참고 첫 쪽이 20%만 참 | 배지 + `□` 뒤의 큰 표가 남은 자리에 못 들어감 | **큰 표를 배지 바로 뒤**로 올리고, 짧은 표·`□`는 뒤로 돌린다 |
| 표 하나가 두 쪽에 걸쳐 반씩 빔 | 6행 이상이라 어느 쪽에도 안 들어감 | **머리행을 복제해 표를 둘로 쪼갠다**(자연스럽게 이어 흐른다) |
| 마지막 `※` 한 줄만 다음 쪽에 남음 | 앞 쪽 채움률이 90%를 넘음 | `※` 문구를 한 줄로 줄이거나, 표에서 1~2행을 압축한다 |

**설계 순서**: ① 배지 → ② 가장 큰 표 → ③ `□`와 작은 표 → ④ `※`.
`□` 제목을 표마다 붙이려는 습관이 지면을 가장 많이 버린다. 머리행이 이미 표를
설명하면 `□`를 생략한다.

### 11-2. 칸 높이는 「추정」이지만 배치를 결정한다

한글은 `<hp:cellSz height>` 를 **그대로 조판에 쓴다**(내용이 넘칠 때만 늘린다).
넉넉하게 잡으면 표가 실제보다 커 보여 **앞 쪽에 들어갈 것도 다음 쪽으로 밀린다.**

맑은 고딕 10.5p 실측 상수(HWPUNIT):

| 값 | 크기 | 뜻 |
|---|---|---|
| 한글 한 글자 폭 | **1050** | 라틴·숫자는 절반으로 센다 |
| 한 줄 높이 | **1120** | 글자 + 줄간격 |
| 칸 상하 여백 | **160** | `cellMargin` 위아래 합 |
| 본문 폭 | 47,313 | = 한글 **약 45자** |

`height = 줄수 × 1120 + 160`. 줄수는 칸마다 세어 그중 최댓값을 쓴다.

### 11-3. 열 너비는 45자를 나눠 쓴다

본문 폭이 한글 45자다. **20% 열 = 9자**밖에 안 된다. 열을 정하기 전에 가장 긴
셀 문자열의 글자수를 세고, 넘치면 열을 넓히는 대신 **줄바꿈 위치를 어절 경계에
직접 지정**한다(`시기` 열의 `법 제14조의4~` / `제14조의13`).

- 칸 문단 정렬은 **LEFT**. `JUSTIFY` 를 쓰면 좁은 칸에서 글자 사이가 벌어져
  「재산의   등록과   변동신고」처럼 찍힌다.
- 표 본문은 본문보다 한 단계 작게(본문 15p → 표 10.5p). 이건 T8이 요구하는 것이기도 하다.
- 머리행은 굵게 + 옅은 채움, 본문 칸은 흰 바탕. **채운 칸에 흰 글자를 쓰면 T10에 걸린다.**

### 11-4. 검증은 채움률로 한다

표를 심은 뒤에는 반드시 쪽별 채움률을 잰다(§10의 PDF 계측을 그대로 쓰되,
**쪽번호 블록을 제외**해야 한다 — 넣으면 모든 쪽이 96%로 보인다).

```python
bs = [b for b in page.get_text('blocks', clip=half) if not re.fullmatch(r'\s*-\s*\d+\s*-\s*', b[4])]
fill = max(b[3] for b in bs) / page.rect.height
```

채움률 **20% 아래인 쪽**은 예외 없이 위 11-1의 세 증상 중 하나다. 글자를 지우기 전에
**표의 순서와 크기를 먼저 본다.**
