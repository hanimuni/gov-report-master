# ⑪ 실측 작성 패턴 — 부처 보고서 원문에서 뽑은 규칙

> `02-writing.md`가 **무엇을 쓸지**를, `10-typography.md`가 **어떻게 앉힐지**를 정한다면,
> 이 문서는 **부처가 실제로 어떻게 쓰고 있는지**를 센 결과다. 충돌하면 이 문서가 이긴다 —
> 여기 있는 숫자는 원문에서 직접 센 것이고, 다른 문서의 규칙은 대개 2차 자료이기 때문이다.
>
> 근거: `assets/samples`의 원본 PDF를 kordoc으로 변환해 블록 단위로 계측.
> 마커가 텍스트층에서 유실된 문서는 계측에서 제외하고 그 사실을 표기했다.

### 1-2. ⭐ 위계별 문장 길이 — 이것이 가장 중요하다

| 파일 | `□` 중앙값 | `○` 중앙값 | `-` 중앙값 |
|---|---|---|---|
| case2 | 25자 | **38자** | 57자 |
| case4 | 36자 | **25.5자** | 48자 |
| case5 | 20자 | **37자** | 70자 |
| case6 | 27.5자 | **36자** | 71자 |

> ⚠️ **위 표는 폐기됐다 — 물리 1행을 잰 값이다.**
> 논리 단락(마커 없는 후속 행을 부모에 병합)으로 다시 재면 값이 완전히 달라진다.
> **정본은 `references/14-content-density.md` §2 (n=315)** 이며 아래가 그 결과다.

```
□   6~34자   중앙 22.  소제목 / (라벨)+방침 / 「개념 : 정의」. 40%가 10자 이하
○  29~67자   중앙 40.  요지. 단어 나열이 아니라 술어를 갖춘 한 문장. 2행 허용
-  30~62자   중앙 40.  ★○와 길이가 같다. 짧아서 -가 아니라 기능이 달라서 -다
·  21~36자   중앙 29.  박스·표 내부. 거의 항상 1행
※  35~63자   중앙 46.  ★가장 길다. 수치·출처·단서를 몰아 넣는 자리
```

> ⚠️ **폐기된 두 규칙 — 다시 살리지 않는다.**
> - 「`-`는 `○`의 1.5~2배」 → **사실이 아니다.** 둘 다 중앙 40자, 평균 1.5행.
> - 「`○`가 60자 넘으면 `-`로 내려라」 → **위험하다.** 정상 `○`의 p75가 67자, 최대 106자다.
>   넘친다고 자르면 내용이 사라진다. **기능이 다른 부분만** `-`로 내린다.
>
> 원전의 유일한 길이 규범은 「한 문장이 **2줄 이내**, 최대 3줄」(『칭찬받는 보고서 작성법』)이다.
> **자수가 아니라 줄 수**가 단위다.

> ⚠️ **여전히 유효한 오류 경고**: `○`를 **명사 나열**로 쓰는 것.
> 짧게 만들려고 조사를 지우면 개조식이 아니라 **조사 누락 비문**이 된다.
> `○`는 술어로 닫는다 — `구축`·`필요`·`불과`·`부재`·`지원`·`기여`.

### 1-3. `□`의 세 가지 용법

```
① 소제목        □ 사행산업 확산 주요 원인
② (라벨) + 방침   □ (연구대상) 세계 최고 수준의 기초·원천기술 확보를 위한 고난도 과제
③ 개념 : 정의     □ 운영위원회 : 산학연 외부 전문가가 참여하는 최고 의사결정 기구
```

### 1-4. `○`는 한 줄 요지 — 실제 사례

```
ㅇ (도전) 실패가능성이 있더라도 성공 시 파급력이 큰 혁신적 연구에 도전
ㅇ (자율) 연구개발 全단계(기획·수행·평가)에서 연구자의 자율성 최대 보장
ㅇ 문화콘텐츠 산업을 선도하는 스타 캐릭터 집중 발굴 육성
ㅇ 사업기간/전문기관 : 2021. 1. 1. ~ 2021. 12. 31.(12개월) / 한국연구재단
o '06년 매출규모는 12.1조원, GDP 대비 1.4%
```

### 1-5. `-`는 `○`를 받아 방법·조건·내역을 편다

```
ㅇ (자격) ICT·SW분야 대학(원)이 설치된 대학 중심의 컨소시엄 구성
 - 주관기관(연구책임자)과 다수의 대학 및 기관이 참여하는 그랜드 컨소시엄 형태
 - 대학 외 국내·외 ICT기업, 연구소, 지자체 등도 자율적으로 추가 구성 가능
```

한 단계 더 필요하면 `·`를 쓴다(사례5).

## 2. ⭐ 서술톤 — 명사형 종결이 82%다

빈 줄로 구분된 **블록 730개**(표 제외)의 마지막 어절 분류:

| 종결 형태 | 건수 | 비율 |
|---|---|---|
| **명사형 종결** (추진/강화/지원/필요/마련…) | 600 | **82%** |
| `~함/~임/~음/~됨` | 11 | **1%** |
| **서술식 `~다/~습니다`** | **1** | **0.1%** |
| 기타(수치·영문·괄호 종결) | 114 | 16% |

파일별 명사형 비율: case1 85% · case2 70% · case3 72% · **case4 91%** · case5 87% · case6 89%

가장 많이 쓰인 종결 명사 상위 15:
```
추진 35 · 강화 23 · 지원 20 · 필요 12 · 마련 12 · 확대 8 · 개최 7 · 현황 7
활용 7 · 확보 7 · 구성 6 · 개선 5 · 지적 5 · 양성 5 · 가능 5
```

### `~함/~임`이 허용되는 세 자리 — 그 밖에는 쓰지 않는다

1. **머리글(보고 취지)** — `…향후 정책방향을 점검·조정함` / `…추진해 나갈 계획임`
2. **조사·설문 결과 인용** — `…순으로 응답함` / `…비율이 높은 것으로 나타남`
3. **전언·판단의 인용** — `…사행성을 심화시키고 있다는 지적`

> ⚠️ 6건 어디에도 **「~한다/~이다」 서술체 본문이 없다.** 개조식 명사종결이 기본값이고
> `~함/~임/~음`조차 1%다. 「서술식으로 풀어 쓰라」는 요구를 받더라도 그것은
> **`-` 항목을 늘려 맥락을 담으라는 뜻**이지 종결어미를 바꾸라는 뜻이 아니다.

## 3. 괄호 라벨 — 6건 중 4건에서 확인

`○ (라벨) 내용` 형식. 라벨은 **2~6자 명사구, 조사 없음, 마침표 없음**.

| 계열 | 실제 라벨 |
|---|---|
| 원칙·방침 | `(도전)` `(자율)` `(개방)` `(협력)` |
| 사업요소 | `(자격)` `(참여인력)` `(계획서 제출)` `(선정기준)` `(권한과 임무)` `(구성)` `(역할)` `(운영)` |
| 정책수단 | `(정책)` `(인재매칭)` `(적응·생활지원)` `(선도기관)` `(관리강화)` |
| 사업개요 | `(사업내용)` `(총사업비/기간)` `(기능)` `(구성안)` `(추진계획)` `(협업계획)` |
| 단계·시점 | `(1차년도 : 기반조성)` `(2차년도 이후 : 본격추진)` |
| 대상·주체 | `(연구대상)` `(과제선정)` `(연구수행)` `(평가)` |

콜론은 값이 붙을 때만 — `(총사업비/기간) : 420억원`

## 4. ⭐ 문제 제시와 대책 연결 — 문제는 3~5덩어리

| 방식 | 사례 |
|---|---|
| 원칙 3개를 박스로 선언 → 같은 3개가 그대로 과제 ①②③ | 1 |
| **한계 ①②③ 번호가 추진사항 ①②③과 그대로 대응** | 2 |
| 단계 흐름도(`⇒`)로 병목 제시 → 전략/과제 정렬표 | 3 |
| **목표 `○` 5개와 과제 `□` 5개가 동일 문자열** | 4 |
| 원인/증상 분리 → 3축 × 5~6수단 격자 → `☞ 별첨N` 연결 | 6 |
| 문제 장 자체를 두지 않음 | 5 |

**문제 덩어리 수는 3~5개.** 단 이것은 **상한이 아니라 하한**으로 읽는다 —
원전은 「문제점은 다각적이고 심층적으로 적되, **최소 3개 이상** 적음」(『실무 유형별 보고서 작성법』)이다.
6개 이상이 실측에 없는 것은 **MECE로 묶었기 때문**이지 못 쓰게 해서가 아니다.

연결에 별도 매핑 설명을 쓰지 않는다 — **번호나 문자열을 같게 만드는 것**이 관행이다.

```
Ⅲ. 한계점          ① 유치·협력 전략 미흡
Ⅳ. 주요 추진사항    ① 전략적 유치 기반 마련      ← 번호가 곧 대응표
```

## 5. ⭐ 수치는 본문이 아니라 각주에 둔다

**본문 `○`/`□`는 "무엇이 문제인가·무엇을 한다"만 말하고, 근거 숫자는 바로 다음 줄 `*`/`※`로 내린다.**

> ⚠️ **내려보내는 것은 「숫자」뿐이다.** 맥락·방법·조건·인과는 `*`/`※`가 아니라 **`-`(본문 15p)** 로 간다.
> 설명까지 각주로 내리면 결재자가 훑을 때 시야에서 사라진다 — 이 오독이 실제 반려를 낳았다.
> 판별: 「없으면 **이해** 못 하는」 문장은 `-`, 「없으면 **믿을** 수 없는」 수치·출처는 `※`.
> 상세는 `references/14-content-density.md` §5.

```
(본문) 수산계고 승선학과는 입학생 부족·재학생 중도자퇴·졸업 후 미승선 등으로 신규 어선원 양성에 어려움
   * '22년 승선학과 입학생 : 정원대비 55%(185명/337명) 모집
   * 승선학과 졸업생수 : ('17) 389명 → ('21) 207명 / 승선자수 : ('17) 106명 → ('21) 61명
```

**예외는 사업 제원 하나** — 기간·예산·규모·인원은 `○ 항목 : 값`으로 본문에 둔다.
```
ㅇ 지원규모 : 약 330명(신규선발 60명 내외)
ㅇ 사업예산 : 31,459백만 원(사업비 30,124백만 원, 기획평가관리운영비 1,335백만 원)
◈ 총사업비(계획) : 5년('21~'25년)간 총 445억원, '21년 45억원
```

`※`와 `*`의 분담: `*`는 정의·출처·산식, `※`는 예외·전제·추정치·국제비교.

## 6. 표는 네 종류만 본문에 남는다

| 본문에 두는 표 | 실제 헤더 |
|---|---|
| 추진일정 | `세부과제 \| 추진일정('22 上/下, '23~24, '25 이후)` |
| 과제×일정×주관 | `핵심 과제 \| 추진일정 \| 주관, 협업` |
| 연차별 예산 | `구분 \| 2017 \| 2018 \| … \| 계` |
| 평가 배점 | `구분 \| 세부항목 \| 평가 기준` |

**통계·시계열·국제비교·기관별 실적은 전부 붙임으로 내린다.**
사례6은 본문 7쪽에 표 3개, 별첨에 13개 — 「본문은 판단, 데이터는 별첨」 원칙의 극단.

## 7. 장 구성 — 전건 공통은 「세부 추진과제」 하나뿐

| 블록 | 6건 중 |
|---|---|
| **세부 추진과제** | **6/6** |
| 문제점·한계 | 5/6 |
| 배경·개요 | 5/6 |
| 목표·기본방향·전략 | 5/6 |
| 추진일정 | 5/6 |
| 붙임·별첨·참고 | 5/6 |
| **기대효과** | **2/6** |
| 해외사례 · 행정사항 · 세부실행계획 | 각 1/6 |

→ 실무 골격은 **`배경 → 현황·문제점 → 목표·기본방향 → 세부 추진과제 → 추진일정 → 붙임`**
→ **기대효과 장은 필수가 아니다.** 넣으려면 과제별로 붙이지 말고 마지막에 한 장으로 모은다(사례1·4).

## 9. 이 문서를 쓸 때의 체크포인트

- [ ] `○`가 29~67자이고 **술어로 닫히는가** — 명사 나열이 아닌가
- [ ] **`-` : `○` ≥ 0.8 인가** — 해결방안 장은 1.0~1.55 (→ `14` §1)
- [ ] **`-`를 거느린 `○`가 절반 이상인가** — 다는 곳은 1~2개씩인가
- [ ] 종결이 명사형인가 — `~임/~함`은 머리글·조사결과 인용에만
- [ ] 문제 덩어리가 **3개 이상**인가 — 6개 이상이면 MECE로 묶어라
- [ ] 문제 번호와 과제 번호가 대응하는가 — 매핑 설명을 쓰지 말고 번호를 맞춰라
- [ ] 근거 **숫자**를 `*`/`※`로 내렸는가 — 단 **맥락·방법은 `-`로** (→ `14` §5)
- [ ] 본문 표가 일정·예산·배점·체계 넷 안에 드는가
- [ ] 쪽당 `□` 2개 이하 · 마커 단락 12~17개 · 공백제외 400자 이상인가 (→ `14` §4)
