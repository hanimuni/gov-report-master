# 템플릿 ③ 상황보고서

> 신속성이 생명. **시간 흐름 = MECE**: 과거 → 현재 → 미래. 초안이 그대로 최종결재권자까지 가므로 사실·추론을 엄격히 구별. 사고법 `references/01`.

> **산출 계약** — 프로파일 `profiles/03-situation.profile.json` · kordoc preset `보고서` --no-cover --no-toc --no-page-numbers · 게이트 방향 `max`. 정본은 프로파일 JSON이다.

## 질문 세트
- Q1: 무슨 사건·상황인가요?(6하원칙: 누가·언제·어디서·무엇을·어떻게·왜)
- Q2: 현재 사실관계는? (피해·영향 규모 — 숫자)
- Q3: 지금까지의 조치는?
- Q4: 향후 전망·추가 위험은?
- Q5: 앞으로의 대응 계획은?
- 공통: 분량(긴급 시 1쪽) / 문체(상황 묘사는 서술식 혼용 가능)

## 본문 뼈대
```
□ 사건 개요            [결론 한 줄] 기준시각 + 핵심사건 + 피해규모(출처)
□ (과거) 발생 경위·조치  6하원칙, 시간순
□ (현재) 피해·영향       (인명)/(공공)/(사유)/(교통) 괄호 라벨 + 표
□ (현재) 언론·유관기관 동향
□ (미래) 향후 전망       ← "정보 + α" 한 줄 (전망·검토방향)
□ (미래) 대응 계획       통제 가능=대책 / 통제 불가=대응전략
[그림·상황도 1개]
```

## 주요상황 서술 방식 (택일)
「주요상황」 본문은 사안 성격에 따라 둘 중 하나로 쓴다:
- **기사형(중요한 것부터)**: 긴급·단발 상황. 핵심 사실·피해를 맨 앞에. (예: 사고 속보)
- **스토리형(시간 흐름·전말 순서)**: 경위 파악이 중요한 사안. 발단→전개→현재를 시계열로. (예: 사고 경위 보고)

## 깨포 점검
- 과거→현재→미래가 MECE로 빠짐·겹침 없이 나뉘는가?
- 제목만으로 사건이 구체적으로 그려지는가?(추상 제목 금지)
- **사실과 추론을 구별**했는가? 모르면 "모른다/확인 중"으로.
- 불필요한 정밀 계산 대신 "약 ○○억 내외"로 신속성을 살렸는가?
- 주요상황을 사안 성격에 맞게 기사형/스토리형 중 골랐는가?
