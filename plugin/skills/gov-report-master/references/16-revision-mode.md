# ⑯ 기존 보고서 보완 — 새로 쓰지 않고 고친다

> **사용자가 완성된 보고서(HWPX·DOCX·MD)를 주며 「보완·점검·반영해 달라」고 할 때 Read.**
> Phase 1~4(유형 확정·인터뷰·생각정리·뼈대)를 처음부터 돌지 않는다. 승인된 뼈대가 이미 문서 안에 있다.

---

## 1. 세 가지 불변 조건

1. **원본에 덮어쓰지 않는다.** 별도 파일로 낸다. 사용자가 말하지 않아도 기본이다.
2. **구조·서술 톤·편집 스타일은 원본이 정본이다.** 장 구성, 항목부호 체계, 배지·박스 형식, 종결 방식을
   우리 템플릿으로 갈아 끼우지 않는다. 우리 규칙과 다르면 고치지 말고 **알린다.**
3. **생성기로 다시 만들지 않는다.** 원본 파일의 문단에 패치한다(`07-form-fidelity.md` §8).
   재생성은 사람이 한글에서 다듬은 조판을 말없이 지운다.

---

## 2. 진행 순서

| 단계 | 하는 일 | 게이트 |
|---|---|---|
| R1 읽기 | 원본을 텍스트로 떠서(`npx -y kordoc@^4 <파일>`) 장·항목 구조와 표기 관행을 적는다 | — |
| R2 점검표 | 요청 항목별로 **무엇이 미흡한지**를 표로 낸다. 고치기 전에 보여 준다 | **G5 대체 — 승인 전 본문 수정 금지** |
| R3 반영 | 승인된 항목만 고친다. 새로 넣은 내용은 검토용 A에 `[AI]` 로 표시한다 | — |
| R4 검수 | §4 정합 점검 + `draft_guard`(텍스트 덤프 대상) + `report-auditor` | G6 |
| R5 산출 | 별도 파일로 저장 → Phase 7 편집 품질 점검 | G7 |

R2가 G5를 대신한다. 뼈대를 새로 승인받는 대신 **무엇을 어디에 더하고 뺄지**를 승인받는다.
장을 신설·삭제하면 뼈대 변경이므로 따로 확인받는다.

---

## 3. 자주 받는 보완 요청과 점검 방법

### 3-1. 문제 ↔ 해결책 대응

문제점 장의 항목마다 개선방안의 어느 과제가 받는지 표로 짝짓는다.

| 문제 (위치) | 대응 과제 | 판정 |
|---|---|---|
| Ⅱ-2 ○ 심사 기준 불명확 | 과제 1-❶ | 대응 |
| Ⅱ-3 ○ 공개 방식 한계 | — | **미대응** |

미대응 항목에 곧바로 과제를 신설하지 않는다. **기존 과제로 설명되는지 먼저 본다** — 설명되면
연결 표기(`→ ☞ 과제 N`)만 더한다. 신설 여부는 사용자가 정한다.

### 3-2. 분석틀(SWOT 등)과 문제 도출의 연결

분석표가 장식으로 남지 않았는지 본다. SWOT이면 교차(SO·ST·WO·WT) 결과가 문제 정의나 과제의
근거로 **본문에서 인용**되는지 확인하고, 표에만 있고 본문이 받지 않는 칸을 적어 낸다.

### 3-3. 개선과제별 개정 대상 표시

제도 개선 보고서는 과제마다 **무엇을 고쳐야 실현되는지**를 한 줄 배지로 단다.

```
❶ 지정 기준을 3개 군으로 구분                【시행령 개정 : 제○조제○항】
❷ 허가제를 신고제로 전환                      【법률 개정 : 제○조제○항 / 예규 제정】
```

- 층위는 **법률 → 시행령 → 시행규칙 → 고시·훈령·예규** 가운데 실제로 손대야 하는 층을 쓴다.
  과태료·벌칙·권리 제한은 법률 사항이다 — 하위법령 개정으로 적지 않는다.
- 조문 번호는 **korean-law MCP로 현행 원문을 열어** 확인한 것만 쓴다. 못 했으면 `{{조문 — 원문 확인}}`.
- 신설 항·호 번호는 현행 조문의 마지막 번호를 확인한 뒤 붙인다.

### 3-4. 신·구조문 대비표 (붙임)

개정이 필요한 조문을 `[현행 | 개정안]` 2단 표로 붙임에 싣는다.

- 같은 조는 한 칸에 모은다. 고치지 않는 항은 `② ∼ ④ (생  략)` / `② ∼ ④ (현행과 같음)` 으로
  표시해 신설 번호의 근거가 표에서 보이게 한다.
- **연쇄 개정을 훑는다.** 고치는 용어·조문을 **같은 조의 다른 항, 같은 법의 다른 조, 하위법령, 타 법령**이
  인용하고 있으면 함께 고쳐야 한다. 한 항만 고치면 개정 목적이 조문상 달성되지 않는다.
- 대비표의 조문 번호는 **본문 배지와 일치**해야 한다.
- 개정안 문구는 전부 `[AI]` 대상이다. 검증 요약표에 「입안 전 법제 검토 필요」로 적는다.

### 3-5. 사실·법령 재검증

수치·사건·법령 인용을 전수로 다시 확인한다(`08-source-research.md`). 틀린 것만이 아니라
**확인해서 맞았던 것도** 검증 요약표에 남긴다. 현행 법령의 표현이 낡아 보여도 원문이 그러면
원문대로 둔다 — **원문을 열어 보기 전에는 고치지 않는다.**

## 4. 고친 뒤 정합 점검 — 덧대면 어긋난다

부분 수정은 문서 안의 짝을 깨뜨린다. 반영한 뒤 아래를 전수로 본다.

| 점검 | 무엇을 보나 |
|---|---|
| **각주 기호의 짝** | 본문의 `*`·`**` 마다 바로 아래에 같은 기호의 각주가 있는가. 본문은 `*`인데 각주를 `※`로 받지 않았는가. 문장을 지우면서 기호나 각주 한쪽만 남기지 않았는가 |
| **용어 표기** | 같은 말을 띄어 쓴 곳과 붙여 쓴 곳이 섞이지 않았는가(`draft_guard` Q28). 약칭은 첫 등장에서 정식 명칭을 밝혔는가 |
| **본문 ↔ 붙임 수치** | 본문의 금액·인원·건수가 붙임 표·대비표와 같은가. 한쪽만 고치지 않았는가 |
| **제목 ↔ 내용** | 「3단계」라 쓰고 병렬 3개 군을 나열하는 식으로 어긋나지 않는가. 총괄 문장의 열거가 아래 항목 수와 맞는가 |
| **과제 간 상호작용** | 한 과제가 다른 과제의 적용 대상을 없애거나 좁히지 않는가 |
| **들여쓰기** | 추가한 줄의 부호·들여쓰기가 이웃 줄과 같은가(전각·반각 공백 혼용 포함) |

각주 기호의 짝은 **마크다운 원고가 아니라 HWPX 본문에서** 생기는 결함이다. 텍스트 덤프를 떠서
본문 기호와 각주 줄을 줄 단위로 대조한다.

---

## 5. 하지 않는 것

- 요청받지 않은 장의 문장을 다듬지 않는다. 눈에 띄는 결함은 고치지 말고 목록으로 알린다.
- 원본의 항목부호 체계를 우리 사다리(`□ → ○ → -`)로 바꾸지 않는다.
- 줄여 달라는 요청이 없으면 기존 문장을 압축하지 않는다.
