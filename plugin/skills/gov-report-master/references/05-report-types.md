# ⑤ 보고서 10종 유형 체계

> 분류 기준: **누가 읽는가(내부/외부)**. 내부 6종 + 외부 4종 = 10종. 종류가 달라도 결국 **4덩어리(Why1·Why2·How·What)** 의 변형이다(→ `01-planning-thinking.md`). 각 유형의 뼈대는 `templates/{NN}.md`, 실제 사례는 `assets/samples/`.

## 【내부용 — 우리 기관 상급자】

### ① 정책검토보고서 → `templates/01-policy-review.md`
- **정의**: 조직의 공식 입장 결정을 위해 실무자가 사전 검토 의견을 올림. 새로 만들면 정책기획, 갈등을 조정하면 정책조정 — 본질 동일.
- **언제**: 제도 도입/활성화 결정, 이해관계 갈등 조정, 중요 의사결정 사안.
- **핵심 구조**: **Why1(필요성) → Why2(실태·원인) → How(정책대안) → What(추진계획)**.
- **흔한 실수(깨포)**: ①남의 다리 긁기(제목과 분석 대상 불일치) ②목적어 혼동("홍보 활성화"≠"홍보") ③원인분석 없이 문제만 ④기대효과=검토배경 복붙.
- **사례**: 「섬세촉진지원금 홍보 활성화 방안」

### ② 계획수립보고서 → `templates/02-plan-establishment.md`
- **정의**: 의사가 이미 결정된 뒤 "취지대로 어떻게 집행할까"를 정리. 세부추진계획, 행사 준비계획.
- **핵심 구조**: 맨 앞에 **I. 기본방향(Why: 핵심메시지·추진방향)** 을 세우고 → II. 개요(How, 각 항목에 "왜?" 부착) → III. 추진계획(What). **"행사에도 Why가 있어야 한다."**
- **흔한 실수**: 메시지(Why) 없이 일시·장소·내용을 관행대로 나열.
- **사례**: 「공사 창립 50주년 기념행사 준비 계획(안)」(핵심 메시지 "Beyond Standard, Toward Quality")

### ③ 상황보고서 → `templates/03-situation.md`
- **정의**: 사건·사고·동향 보고. **신속성** 때문에 중요(초안이 그대로 최종결재권자까지 감).
- **핵심 구조(시간=MECE)**: **과거(사건개요·조치) → 현재(피해·언론·유관기관) → 미래(전망·대응전략)**.
- **흔한 실수**: 상황만 나열(스토리 없음) / 추상적 제목 / 의견을 사실처럼 / 불필요한 정밀 계산(→ "약 150억 내외").
- **원칙**: 사실·추론 구별, 모르면 모른다고. "정보 + α(전망·검토방향)" 한 줄.
- **사례**: 「연수원 신축현장 붕괴, 10명 추락·중상」

### ④ 개요정리보고서(1쪽) → `templates/04-summary-onepager.md`
- **정의**: 이미 결정된 내용을 **1쪽으로 압축**. 질의답변 참고자료, 회의안건 붙임. "10쪽은 매일 안 써도 1쪽은 매일 쓴다."
- **핵심 구조**: 4덩어리를 1쪽에(I.개요·현황=Why1 / II.추진상황=Why2 / III.개선방향=How / IV.추진계획=What). **A.짧을수록 확실히 B.많이 버린다 C.더 짧게.**
- **흔한 실수**: 서술형으로 빽빽하게 / 1.5쪽 초과 / 만연체("~하였고 ~하였으며").
- **사례**: 「지원금 실적부진 원인과 향후 대책」(질의답변 1쪽)

### ⑤ 회의 참고자료 → `templates/05-meeting-reference.md`
- **정의**: 회의에서 참석자 발언을 돕는 글. 안건 검토자료, 타 부서 의견 검토, 인사말씀 요지. **즉석 참고 가능**해야 함.
- **핵심 구조(두괄식+쟁점)**: 쟁점별 **수용/불수용 → 주장 → 근거(논리적=규정·이론 / 분석적=통계) → 사례(종적=우리 과거 / 횡적=타 기관)**. 미괄식 금지.
- **흔한 실수**: 일반적 필요성을 매 쟁점 반복 / 분량 채우려 부풀리기.
- **사례**: 「타 부서의견 검토자료: 지원금 활성화 지원팀 신설」

### ⑩ 결과보고서 → `templates/10-result-report.md`
- **정의**: 시행한 정책·사업의 **추진결과(성과)** 를 보고. 기획보고서가 '사전 제안'이면 결과보고서는 '사후 성과' — 대칭 구조.
- **언제**: 사업·대책·행사 종료 후 실적·완료 보고, 점검·조사 결과 보고.
- **핵심 구조(gap-closing)**: 개요(두괄식 결론) → 추진배경 → 현황·문제점(**목표-현실 격차를 통계로**) → **추진결과(격차를 얼마나 줄였나·정량)** → 기대효과(정량 성과·시사점) → 조치사항.
- **흔한 실수**: 한 일을 나열만 하고 '성과(격차 축소)'를 정량화하지 않음 / 계획 대비 대조 없음.
- **필수**: **사진·통계치**로 신뢰도 확보. 기대효과는 절감액·건수 등 **정량**으로 못박기.
- **사례**: 「2018년 산불방지대책 추진결과」·「비정규직 통계조사 결과 분석」(→ `assets/samples/결과보고서/`)

## 【외부용】

### ⑥ 보고자료(→상급기관) → `templates/06-external-report.md`
- **정의**: 상급기관에 업무 보고. 주요업무 추진현황, ○○년 추진계획.
- **핵심 구조**: 중간 목차에 **차별 키워드(협업·지역·현장)** 를 박아 의도를 드러내고, 나열식을 스토리화(문단 5줄 이내, 키워드 색·고딕 강조).
- **흔한 실수**: 내용이 대동소이해 "특별한 거 없으면 생략" 압력에 밀림 → 우리만의 차별 키워드로 승부.
- **사례**: 「강원지청 2013년 주요업무 추진계획」

### ⑦ 협의자료(→타 기관) → `templates/07-external-consultation.md`
- **정의**: 기관 대 기관으로 우리 업무를 설명·설득. 외부 회의자료, 예산 설명자료.
- **핵심 구조**: 추진상황·향후계획을 각각 압축해 **"내가 하는 것 vs 남(타 기관)이 하는 것"** 스토리로. 모든 문장 2줄 이내.
- **흔한 실수**: "30분이면 쓰지"라는 대충하는 습관.
- **사례**: 「(강원도청 제출) 화학사고 등 중대재해 예방 회의자료」

### ⑧ 설명자료(→국민) → `templates/08-external-explanation.md`
- **정의**: 국민·언론 대상. 보도자료, 기자간담회 자료. 사실에도 취사선택의 의도가 있으므로 스토리텔링식으로.
- **핵심 구조(역피라미드 3층)**: **Fishing(제목·부제·Lead) → Reasoning(Body1~3) → Message(Quote 인용)**. 가장 특징적 단어에 색·크게 강조.
- **흔한 실수**: 단순 사실 나열만 / '밝혔다'로 기자처럼 씀.
- **사례**: 「"열린 고용! 열린 인사" 고용부의 "열일(熱日)" 행보」

### ⑨ 말씀자료(→행사 참석자) → `templates/09-external-speech.md`
- **정의**: 행사 공식 스피치용. 축사·격려사·기념사·인사말. **자료 없이 듣는 청중** 상대.
- **핵심 구조**: 사고 양상에서 **3키워드(예: 현장·기본·완벽)** 를 뽑아 한 줄로 압축한 뒤 한자성어·중의로 확산(현장=우문현답 / 기본=사칙연산 / 완벽=安全).
- **흔한 실수**: 세부사업을 장황하게 나열(자료 없이는 이해 불가).
- **사례**: 「산업안전 행사 3분 인사말」

> **외부 공통 3요소**: 기획(나열→덩어리+스토리) / 쓰기(문장 2줄 이내, 키워드 부각) / 편집(왼쪽 정렬·호흡 끊기, 순서어 고딕, 키워드 색).

## 유형별 표준 골격 시퀀스 (뼈대 잡을 때 기본값)

4덩어리를 실제 목차로 펼칠 때 아래 정규 순서를 기본값으로 삼는다(상황에 맞게 가감).

| 성격 | 표준 목차 순서 |
|---|---|
| 추진계획(정책검토) | 추진 배경 → 현황·문제점 → 추진 목표·방향 → 추진 과제 → 세부 실행 계획 → 기대 효과 → 행정 사항 |
| 방안 보고서 | 현황 → 문제점 → **원인** → 방안 → 세부 실행 계획 → 장애 요인·극복책 → 기대 효과 → 행정 사항 |
| 운영·계획수립 | 개요 → 운영 목적·방향·내용 → 운영 일정 → 평가 계획 → 행정 사항 |
| 행사·회의 | 행사 개요 → 시간 계획(진행) → 준비 계획 → 행정 사항 |
| 결과보고 | 개요 → 추진배경 → 현황·문제점(격차) → 추진결과 → 기대효과 → 조치사항 |

**세부 실행 계획 표기 관용**: 항목 앞머리에 `【태그】` 또는 `(키워드)` 라벨을 붙여 "무엇에 관한 항목인지" 먼저 보여준다(유목화). 예) `가.【도로환경 고도화】 …` / `◦ (사전-사후 조사) …` → 스캔 가독성 급상승.

**기대 효과 표기**: `(단기)/(장기)` 또는 `【가시 성과】/【거시 전망】`으로 정량·정성 이원화, `➡`로 파급 연결.

## 작성 시작 전 누락 방지 체크리스트 (박종덕 실무 유형별)

**추진배경 11요소** — 배경을 쓸 때 아래에서 해당되는 근거를 빠짐없이 챙긴다:
① 법령 근거 ② 정부 정책(기본·중장기·시행계획) ③ 행정환경 변화 ④ 경쟁·유사기관 동향 ⑤ 대통령 공약·지시·국정과제 ⑥ 기관장 공약·지시 ⑦ 감사·평가 지적 ⑧ 언론·국회·시민단체·국민 요구 ⑨ 연구보고서 제언 ⑩ 결과보고서 반성(한계) ⑪ 보도된 사건·사고.

**개요 11요소** — 개요를 쓸 때: 사업명 / 일시·기간 / 장소 / 대상 / 예산 근거 / 법적 근거·목표 / 관련 기관 / 수행 방식 / 실행 체계 / 실행 절차 / 주요 과제.

**보고 취지(글상자)**: 제목 아래 글상자(위 실선·아래 이중선)에 작성 까닭을 4행 이내로(문단구분·들여쓰기·마침표 없이), 4행 초과 시 `◈`·`▣`로 문단 구분. '취지(까닭) / 개요(요점) / 요약전(간추림)'은 성격이 다르니 구분해 쓴다.

## 매핑표 — 10종 ↔ 구(舊) 실무 4대유형 (호환·마이그레이션용)

과거 자료가 4대유형(정책·상황·회의·행사)으로 되어 있어도 아래로 대응시킨다.

| 10종(신) | 대상 | 구 4대유형 | 비고 |
|---|---|---|---|
| ① 정책검토 | 내부 | 정책(기획+조정) | 신규=기획, 갈등=조정 |
| ② 계획수립 | 내부 | 정책(집행)·행사(준비) | 신설 축 |
| ③ 상황 | 내부 | 상황 | 1:1 정합 |
| ④ 개요정리(1쪽) | 내부 | 정책(요약형) | 신설 축 |
| ⑤ 회의참고 | 내부 | 회의(자료) | 1:1 정합 |
| ⑩ 결과보고 | 내부 | (실적·완료 보고) | 신설 축 |
| ⑥ 보고자료 | 외부 | (대외 업무보고) | 신설 축 |
| ⑦ 협의자료 | 외부 | 회의(외부) | 응용 |
| ⑧ 설명자료 | 외부 | (대국민 보도) | 신설 축 |
| ⑨ 말씀자료 | 외부 | 행사(말씀) | 1:1 정합 |
| (회의결과) | 내부 | 회의(결과) | ③ 상황에 흡수하거나 별도 정리 |

**정합 강한 축**: ③상황, ⑤회의참고, ⑨말씀 — 구 골격에 4덩어리 스토리를 얹으면 됨.
**신설 축**: ②계획수립, ④개요정리, ⑥보고자료, ⑧설명자료, ⑩결과보고 — 신규 방법론의 핵심 확장.
