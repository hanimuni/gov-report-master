## 1. 긴 문장을 쪼개는 방법 — 우선순위 4단계

46자 초과를 **검출만 하고 처방이 없던** 공백을 메운다.

```
① 「및」·쉼표를 기준으로 자른다
② 연결어미(~하고, ~하며, ~어서)를 종지부로 바꾼다
③ 부사절(~으로 인해, ~에 따라)을 앞으로 빼 별도 문장으로
④ 두 개 이상의 개념이 들어 있으면 문장이 아니라 `-` 항목으로 쪼갠다
```

### 자수 구간 3단 (⚠️ 이 값의 출처)

| 구간 | 조치 |
|---|---|
| ~34자 | 정상 |
| **35~45자** | **검토 대상 — 사용자에게 표시**(그동안 빠져 있던 절차) |
| 46자~ | 분리 |

> ⚠️ **35~45자·46자는 external이 본문 11pt 기준으로 산출한 값**이다(`layout-rules.md:12`).
> 우리 본문은 실측 **15p**이므로 한 줄에 들어가는 글자 수가 더 적다.
> 따라서 46자는 **금지선이 아니라 경고선**으로 쓰고, 게이트 임계는 `초과율 ≤10%`를 유지한다.
> (`10-typography.md`의 「46자 초과 금지」 표현은 이 문서 기준으로 완화한다.)

한 문장 **2줄 이내**(`02-writing.md`)와 46자는 단위가 다르다. 2줄 ≈ 92자이므로 **둘 다 만족**해야 한다.

## 2. 페이지 걸침 방지 — 붙여야 하는 5단위

이 다섯 묶음은 **쪽을 넘겨 갈라지면 안 된다.**

```
① □ 소제목 + 그 아래 첫 ○
② 표 헤더 + 첫 행
③ 그림 캡션 + 그림
④ 인용·음영 박스의 내용
⑤ 1쪽 보고서 전체
```

`style_guard`가 잡지 못하는 항목이므로 **Phase 7에서 조판을 열어 눈으로 확인**한다.

## 3. 1쪽으로 줄이는 순서 — 5단계

분량이 넘칠 때 **본문을 깎기 전에** 이 순서를 밟는다.

```

③ 동의어·중복 표현 압축

⑤ 그래도 안 되면 양식 변경을 권고 — 자동으로 바꾸지는 않는다
```

## 6. 작성자 메타 — 머리말에 문서 성격을 넣지 않는다

> 문서 상단 날짜 옆은 **`작성 부서 / 팀 / 작성자`** 영역이다.
> **이 자리에 임의의 문서 성격이나 주제를 넣지 않는다.**
> 사용자가 주지 않으면 템플릿의 기존 조직명을 보존하거나 확인한다.

```
✅  < ’26. 1. 27.(화), 디지털혁신부 AI기획팀 >
❌  2026. 1. 27.(화)  ·  정책검토(안)  ·  디지털혁신부
```

> ⚠️ **충돌 판정**: `06-hwpx-output.md`의 「머리말 = 일자·**보고서 성격**·부서명」은 **폐기**한다.
> 「중고딕 14p」라는 머리말 글꼴 값도 실측 근거가 없어 **삭제**한다.
> kordoc `--report-info`에 넘길 내용은 **날짜 + 부서(+담당자)**까지다.

필드는 `authoring.date / department / team / name`으로 분리해 다룬다.

## 7. 문단 역할을 글머리 기호보다 먼저 판정한다

| 규칙 | 내용 |
|---|---|
| 역할 우선 | 기호를 먼저 고르지 말고 **이 문단이 무슨 역할인지** 먼저 정한다 |
| 동급 동기호 | **`첫째/둘째/셋째`는 같은 수준의 과제** — 반드시 같은 글머리 기호 |

| 재사용 우선 | 템플릿에 이미 있는 표현 수단을 먼저 쓴다 |

> Q8(같은 depth 마커 2종)은 잡지만 **같은 역할인데 다른 depth에 흩어진 경우**는 못 잡는다.

## 11. 「적의를 보이는 것들」 4종

문장을 무겁게 만드는 네 가지를 걷어낸다.

| 대상 | 전 → 후 |
|---|---|
| 접미사 **`-적`** | 「효율**적**인 운영」 → 「효율 운영」 |
| 조사 **`의`** | 「제도**의** 개선**의** 필요성」 → 「제도 개선 필요」 |
| 의존명사 **`것`** | 「검토할 **것**임」 → 「검토 예정」 |
| 복수 **`들`** | 「기관**들**이」 → 「기관이」 |

> **한 문장에 `의`가 2번 이상이면 반드시 점검**한다. 기계 검사가 가능하다.

> 이 4종은 **문장 무게**를 다룬다. **어휘 자체가 행정용어인지**는 별도 축이다 —
> 비유·구어체·고유어 동사(`조이고`·`어긋나`·`맡기다`·`메우다`) 금지는 → `15-administrative-terminology.md`

### 판단·예정 표현 압축

```
~할 것으로 보입니다   → ~ 예상
~할 필요가 있습니다   → ~ 필요
~하고자 합니다        → ~ 추진
~할 예정에 있습니다   → ~ 예정
~하기로 하였습니다    → ~ 확정
~에 대한 검토가 필요   → ~ 검토 필요
~을 통하여            → ~로
```

### 제목은 명사형으로, 문장이 아니라 검색어처럼

```
❌ 청년 어선원을 육성하기 위한 방안을 마련하고자 함
✅ 청년 어선원 육성 방안
```

## 12. 서술 톤 — 단정의 강도

우리 규칙은 문장 **구조**만 다루고 **단정의 강도**를 다루지 않았다.

| 조정 | 전 → 후 |
|---|---|
| 단정 완화 | 「왜곡이 발생함」 → 「고평가될 **소지가 있음**」 |
| 동사 겸손화 | 「설계함·구축함」 → 「**제안함·제시함**」 (제3자 행위는 원동사 유지) |
| 명칭 명시 | 약칭 단독 사용 금지 — 첫 등장에 정식 명칭 |

**헤지어 4범주는 지우면 안 된다** — 근사(`약`·`내외`), 역접(`다만`·`반면`), 강조(`특히`), 가능성(`~로 보임`).
완화한다고 헤지어를 빼면 **사실 왜곡**이 된다.

국회 검토보고서 계열의 어미 삼분법을 그대로 쓴다 — 사실 `있음` / 성격 규정 `것임` / 평가 `보임`.

## 13. 문서 재활용(작년 → 올해) 점검

신규 작성만 다루던 공백을 메운다. 7분류로 표시한다.

| 표시 | 유형 |
|---|---|
| 🔴 | 원본 자체의 오류 |
| 🟠 | 연도 미갱신 |
| 🟡 | 날짜·요일 불일치 |
| 🟢 | 내용 갱신 필요 |
| 🟣 | 명칭 혼용 |
| 👤 | **인물명** |
| 🔵 | 확인 필요 |

세 규칙:
1. **인물명 확인을 생략하지 않는다** — 전임자 이름·연락처가 남아 있을 확률이 매우 높다. 전화번호는 기본 마스킹
2. **섹션 타입별 날짜 검증** — 과거 실적(PAST)은 연도를 제외하고 요일만 검증, 참조문서번호는 전체 제외
3. **최빈 표기 ≠ 공식 명칭** — 오타가 최빈값일 수 있다

## 14. 양식 선택 — 결정 순서

```
① 사용자가 명시 지정했는가
② 참조 파일이 있는가 → parse_form 으로 빈칸 유무 판정
     빈칸 있음 = 양식형(칸을 채운다)
     빈칸 없음 = 서식 추출형(빈 골격만 가져온다)
③ 분량·키워드로 추정
④ 최종 확인
```

`07-form-fidelity.md`의 hard/soft(첨부 유무)만으로는 **「빈칸 있는 양식」과 「서식만 있는 문서」**를 가르지 못한다. ②의 판정을 추가한다.

**양식 변경이 필요해 보여도 자동으로 바꾸지 않는다** — 옵션으로 제시한다.

## 15. 자동 변환과 신뢰도 등급

게이트가 검출·보고만 하던 것을 **자동 적용 가능 여부**로 나눈다.

| 신뢰도 | 처리 |
|---|---|
| 높음 | 자동 적용 (날짜 0 패딩 제거, 영문 단위 공백, 24시간제 등) |
| 중 | **Before/After를 보여 주고** 사용자 확인 |
| 낮음 | `※` 표시만 남기고 빌드는 진행 |

### 양식 미준수 처리 4단계

```
① 위반 내역을 표로 제시
② 자동 수정은 Before/After 비교를 함께 보인다
③ 수동 검토 항목은 ※ 로 표시한 채 빌드를 진행한다
④ 빌드를 막지 않는다
```

### 장르 가드

명사형 종결 변환은 **시행문·이메일에 발동하지 않는다.**

## 17. 결합형 보고 — 우리 10종에 없던 유형

완료된 **결과**와 앞으로의 **운영계획**을 함께 결재받는 문서다.

```
추진 배경 → 추진 경과 → 주요 내용 → 향후 추진 계획 → 붙임
                          ├ 가. 계약 체결 결과
                          └ 나. 운영 계획
```

10종에 새 유형을 만들지 않고 **⑩ 결과보고의 변형**으로 다룬다 —
「주요 내용」 아래에 결과와 계획을 나란히 두는 것이 특징이다.

## 18. 근거 충돌 점검 — 고유명사까지

Q7(산술 일치)은 숫자만 본다. 다음도 함께 본다.


## 19. 충돌 39건 판정 요약

| 사안 | 판정 |
|---|---|
| 본문 글자 15p vs 11pt | **15p** (부처 3건 실측). external 11pt는 1쪽 보고 기준 |
